# Steam connection, import and sync

The review is a large native dialog with focus containment and shared enter/exit motion. Complete later saves the draft and dismisses it; Cancel import removes the connection through the normal cancellation path. Server-owned `steam_details` jobs continue while the dialog is closed or the page is left. A visible progress bar tracks settled achievement results, and warm caches skip provider work.

Imports default to Completed, with an explicit status selector. Selected games propose the last-played calendar date in the browser timezone as their completion date. The shared CalendarDateInput edits that proposal or discards it; unselected games show no completion-date control. The submitted selection includes the exact dates shown, preventing a timezone change or late background result from changing the approved outcome. This applies to the one-time import; future automatically added games retain their Planning/first-play rules.

Steam uses the existing connection rows, account pull schedule, cancellation and sync-job status. Its private `steam_connections` extension owns onboarding snapshots, selections and source checkpoints. The first import never passes through the movie/series mapping importer: `steam.app` identities resolve existing catalogue games or create Steam-rooted games directly. Existing non-independent catalogue identities retain their tracking rules.

The importer shows the complete public library immediately after its profile/library check, progressively mounting cards. Achievement counts load separately in four-game requests; only the counts show skeletons. The default selection is playtime >= 30 minutes OR unlocked achievements >= 1. Arriving counts update automatic choices while card overrides retain priority until Reset. Drafts persist on the server, with tab-local recovery for reloads during the debounce. Import submits the exact visible selection so late counts cannot add extra games. Unavailable achievements remain unknown and never fail the library. Optional missing release dates use existing catalogue/public cache data before shared public store responses for exposed cards. Public posters go directly to Steam's CDN.

Sync updates selected games. The optional **Automatically add new games** setting also adds identities discovered after the first import. The initial complete library is the boundary: declined games are never backfilled. New games start in Planning; once their Steam time exceeds 30 minutes, they move to Playing and receive the current calendar date in the connection's browser timezone. This transition is consumed once and subsequent manual status/date choices are preserved. Removing an entry locally never causes sync to recreate it. The first playtime observation uses the greater of existing time and Steam time; later positive Steam deltas preserve other manually recorded time. Per-connection checkpoints remain distinct from local list totals, including a playtime high-water mark and last-played timestamp when Steam supplies one.

`steam_player_games` durably caches authoritative progress by viewer, Steam profile and app, including request leases and failure cooldowns. Reopening/reconnecting reuses this evidence; another viewer never receives it. Public app names, posters, release evidence and achievement denominators go into shared metadata even for declined games. User lists store unlocked counts; percentages are derived from the current public denominator. Added/withdrawn achievements invalidate stale counts and can update percentages without treating an older schema read as newer evidence.

After import and sync, public artwork repair uses IGDB's explicit Steam references in batches of at most 100. Unique canonical references can supply covers without merging game identities or changing private entries. If no unambiguous cover is available, a verified Steam header can serve as fallback artwork. Header checks use bounded concurrency and never download the image through our server. Ambiguous/empty results are cached for 30 days; provider failures stay retryable. Existing canonical and protected artwork wins, and a subsequent OwnedGames refresh cannot replace a verified cover with its guessed Steam URL. Reviews reuse that shared cover. Steam achievement schemas may legitimately have an empty `gameName`; completeness depends on the explicit validated achievement array.

## Public API and request cost

- [GetPlayerSummaries / ResolveVanityURL](https://partner.steamgames.com/doc/webapi/ISteamUser): one profile check, plus one vanity resolution if needed. No Steam password, user API key or cookies are required.
- [GetOwnedGames](https://partner.steamgames.com/doc/webapi/IPlayerService): one request supplies library identities, names and playtime, including played free games. Profile and Game details must be public. An absent `game_count` is unavailable evidence; an explicit zero is a valid empty library.
- [GetPlayerAchievements](https://partner.steamgames.com/doc/webapi/ISteamUserStats): one request per uncached or changed game, with unlocked and total counts. The API returns the game's player achievement rows in one call; the importer stores the aggregate, not a call per achievement. The picker dynamically checks the library, including zero-playtime games. Optional calls use one attempt and a six-second timeout; failures have a 15-minute cooldown and preserve usable cached progress. All ordinary-key calls use `api.steampowered.com`.
- A live beta probe on 2026-11-02 found `GetAchievementsProgress` GET returned 405 and POST returned 401 with the working ordinary Web API key (form, query and header variants). That method was absent from the supported-method list for the key. The implementation therefore uses the working per-game API and requires no Steam user token.
- The documented public player interfaces do not expose custom client library collections. The importer therefore defaults to playtime, with alphabetical and achievement-completion sorting.
- [Valve's API terms](https://steamcommunity.com/dev/apiterms) allow 100,000 calls/day. `STEAM_DAILY_BUDGET` defaults to 90,000, shared across server Steam provider requests. Existing cross-process provider pacing and cooldowns also apply. Player responses explicitly bypass shared HTTP caching.

A 15-minute account interval produces 96 library calls/day per active connection, plus per-game achievement checks for changed playtime or an available changed last-played timestamp. Missing timestamps never replace playtime comparison. Quiet games are rechecked after a day for delayed/offline unlocks and independent achievement-total changes. At most 100 achievement requests are admitted in a pass, ordered by activity then oldest check; unprocessed changes remain due. A quiet 1,000-game selection is approximately 1,096 player API calls/day, versus 96,096 calls/day for a complete per-game scan every 15 minutes. This is an estimate, excluding initial import, failures, profile checks and other Steam metadata. Daily fallback is eventual, not a promise that unchanged-playtime achievements arrive within 15 minutes.

The original beta failure was an HTTP 500 for app 1966720 at 164/180 games. Achievement preparation previously gated the picker and retried the failed batch; periodic whole-library checkpoints caused resume to repeat earlier games. Preparation now does no achievement requests, and each game's result/cooldown is persisted independently.

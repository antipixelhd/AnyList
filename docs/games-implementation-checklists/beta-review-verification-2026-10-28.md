## Mapping implementation

The new public reference index stores immutable source generations, numeric IGDB IDs, IMDb IDs, normalized primary/original/alternative names, years and retained claim provenance. Publication is atomic after completion, observation-time and row-count checks; failures retain the previous active generation. Published data cannot be edited. Retention is active plus one previous publication, with abandoned staging cleanup after two days. Migration: `mt070_game_mapping_index`.

The importer streams the official IMDb basics/AKAs feeds outside the application process and keeps only video games. All AKA evidence is retained; only suitable original/display/alternative names enter matching. The measured snapshot contains 50,788 titles. Its compact transfer is approximately 2.34 MB compressed; the reference table and indexes occupy 58,884,096 bytes in disposable PostgreSQL. A single diagnostic EXPLAIN used the GIN indexes for normalized-name and IMDb-ID lookup, with execution times 0.087/0.067 ms. These are individual database samples, excluding application/network cost.

Wikidata identity claims already retrieved by normal acquisition are periodically projected into the local index every six hours, with no HTTP work or cast-payload transfer. That partial graph is never treated as exhaustive reverse discovery. Explicit CLI imports support external Wikidata exports and complete compact IMDb subsets. Full IMDb feed parsing/network downloads are operator-invoked rather than an automatic workload on the shared VPS; source age is enforced and stale imports cannot certify a new mapping.

Matching requires complete bounded candidate retrieval through both search and exact-name branches, exact primary/trusted-alias spelling, compatible release evidence, known work type and no unresolved competitor. Missing years, unknown types, truncation and provider errors remain unresolved. Numerals, word boundaries, subtitles and plus signs are preserved. Fuzzy discovery never proves identity. Reverse resolution checks both the local IMDb candidate set and the full IGDB candidate set, then applies the existing game/expansion eligibility rules.

Spacelords' two IGDB records retain separate catalogue identities. Their reciprocal aliases and shared Steam app 436180 establish historical rename scope; the current primary title selects IGDB 109257. This is a general evidence rule, without title-specific seeds or a forced merge. Store IDs are namespace-qualified; no undocumented IMDb Steam/console fields or paid API access are assumed.

Automatic bindings record matcher version and supporting identities/query/name scopes. Changed imports or refreshed candidate scopes mark affected automatic evidence stale and request reevaluation. Current policy is enforced when reading verified bindings. Unknown support retains already usable public participation but cannot justify new verified participation; confirmed contradictions quarantine public evidence. Reviewed decisions and private notes/playtime/achievements remain separate. Publication checks the current support generation/fingerprint atomically, and credit workers preserve newer revalidation requests when a mapping changes during provider acquisition.

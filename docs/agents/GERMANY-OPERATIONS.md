# Germany: operational/privacy and attribution audit

Source/code review: 19 October 2026. Non-commercial operation as described by the operator. This is an implementation checklist, not confirmation that an installation meets every legal obligation. Real infrastructure, contracts and actual network behavior must be checked before promoting beta.

## Findings implemented on beta

- Public `/impressum`, `/privacy`, `/cookies`, `/credits`, reachable without login or the logged-out browsing flag. Footer links shared across the main, settings and authentication shells; no primary-navigation expansion.
- Operator/contact/hosting/retention/transfer disclosures come from six explicitly projected `LEGAL_*` backend settings. Real values belong only in ignored `.env` / private deployment configuration, never source control. `/legal/config` intentionally exposes only these public disclosures. Missing facts leave a visible draft marker, not fabricated legal facts.
- No advertising/analytics libraries, third-party font loading or analytics endpoints were found in the application paths inspected. This does not establish absence of tracking in the reverse proxy, CDN or external image services.
- Login (`token`, preview-prefixed when applicable): seven-day browser cookie; OIDC state/return: ten minutes. Display/time/date/streaming-region preferences: up to one year. Region defaults use browser time zone/language, not GPS. Local/session storage and service-worker/browser cache also exist. Inventory is on `/cookies`; revisit it when storage purposes change.
- YouTube, Vimeo and directly embedded external video URLs in profile biographies instantiate players automatically (iframes may use lazy loading). A consent implementation was explored, then fully reverted at the user's explicit request. **This remains an unresolved compliance issue**, not a consent exemption. No video-consent UI or persisted provider approvals ship. Third-party artwork and arbitrary profile images remain direct requests and need their own GDPR assessment. Do not claim this pass blocks third-party network traffic.
- Credits use TMDB's approved unmodified blue-short SVG, locally hosted to avoid another external request, the required disclaimer, JustWatch credit, TheTVDB and TVmaze credits, CC BY-SA link/change notice, and links for optional adapters. Existing source links on media/contributor pages are retained.

## Cookie conclusion and limits

[§25 TDDDG](https://www.gesetze-im-internet.de/ttdsg/__25.html) requires prior consent for terminal storage/access unless an exception applies, including strict necessity to supply a service expressly requested by the user. It covers local storage as well as cookies. A generic information-only banner is not a substitute for consent and is not inherently required merely because login cookies exist. Current core functional storage does not justify an indiscriminate accept-all banner. Check each new purpose individually; no legitimate-interest balancing under GDPR can substitute for §25 consent where required.

[DSK guidance](https://www.bfdi.bund.de/SharedDocs/Downloads/DE/DSK/Orientierungshilfen/OH_Digitale-Dienste.pdf?__blob=publicationFile&v=1) and [BfDI's embedded-video guidance](https://www.bfdi.bund.de/SharedDocs/Downloads/DE/DokumenteBfDI/Rundschreiben/Allgemein/2023/Rundschreiben-Telemedien-02-2023.pdf?__blob=publicationFile&v=5) support separating functional storage from optional embedded providers. `youtube-nocookie.com` and `loading=lazy` alone do not establish consent compliance. Automatic profile embeds remain unchanged by request. Assess and resolve the need for consent, an alternative legal basis where actually available, or disabling/linking the embeds before claiming full compliance.

## Facts still required before main/production approval

1. **Operator identity/address:** no revenue does not itself remove disclosure duties. [§18(1) MStV](https://www.gesetze-bayern.de/Content/Document/MStV-18) requires name/address where the service is not exclusively personal/family use. [§5 DDG](https://www.gesetze-im-internet.de/ddg/__5.html) has its own business-service scope. Confirm the service's actual scope; do not publish an invented address or assume a contact email alone suffices. Editorial-responsibility, register, VAT-ID or regulated-profession fields are conditional, not added speculatively.
2. **GDPR notice and operations:** confirm controller/contact, purposes and bases, actual recipients, countries/transfer safeguards, concrete retention/deletion and backup periods, rights handling and complaints. [GDPR Arts. 5, 6, 12–22, 28, 30, 32–35, 44 ff.](https://eur-lex.europa.eu/eli/reg/2016/679/oj/eng). Keep a processing/recipient inventory, appropriate processor contracts, security/access controls, incident/72-hour notification procedure where applicable, export/deletion handling, and assessment of any DPO/DPIA duty. Do not assert a DPO or DPIA is universally required for this site.
3. **Infrastructure:** identify VPS, DNS/CDN/WAF, email/SMTP, SSO, backup/storage vendors and locations. Review any Cloudflare/CDN bot/security cookies or injected scripts from actual responses; no provider configuration was changed or inferred in this pass. Check logs and backup expiry operationally. Remote artwork exposes visitor IPs; a credits link is not a GDPR legal basis.
4. **User content:** public profiles, comments and lists may require analysis of hosting/intermediary status under the [DSA](https://eur-lex.europa.eu/eli/reg/2022/2065/oj/eng), including contact/notice-and-action and reasons for moderation decisions where applicable. Non-commercial status and small-provider exemptions must be assessed against the actual service; do not declare automatic exemption or add obsolete NetzDG/ODR boilerplate. Establish a report/removal contact and process before opening public user content widely.
5. **Accessibility/consumer scope:** evaluate [BFSG §§1–3](https://www.gesetze-im-internet.de/bfsg/) if an in-scope consumer service/e-commerce offering is introduced, including the statutory microenterprise service exemption. A free tracker is not automatically every kind of covered e-commerce service. No paid-subscription/checkout or universal dispute-resolution statements were invented. Reassess if monetization, contracts or audience change; assess youth protection if age-restricted material is publicly exposed.
6. **License/account scope:** verify the operator's actual API project keys/subscription licenses, restrictions on cached/redistributed data, image rights, and any commercial-use change. Attribution does not itself grant a license. Optional adapters are supported code, not proof they are enabled in production.

## Configure and verify

- Set `LEGAL_OPERATOR_NAME`, `LEGAL_OPERATOR_ADDRESS`, `LEGAL_CONTACT_EMAIL`, `LEGAL_HOSTING_DETAILS`, `LEGAL_RETENTION_DETAILS`, `LEGAL_TRANSFER_DETAILS` only in private `.env` or deployment secrets. Quoted `\n` values support multiline text. Only these intentional public disclosures are returned by `/legal/config`. They are not private once rendered on the site; `.env` keeps them out of Git, not out of the legally required public notice.
- Standard Docker Compose examples forward these variables from the private environment. Custom beta deployment must do the same or mount its private `.env` for the backend. No production environment was edited here.
- Verify anonymous legal pages, auth/settings/main footer, desktop/mobile wrapping, existing automatic video behavior, script-free legal-page access, and no credentials in HTML/API output. Run neighboring frontend/backend tests and build/type checks.
- Only beta should receive this work until operator facts and the operational/contractual questions above are resolved. Missing-field markers are intentional; they must not be mistaken for a finalized privacy notice.
